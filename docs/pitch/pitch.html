The problemx402 pays after the handler succeeds — and "succeeded" is not "correct"

  • x402's standard exact scheme settles the moment the HTTP handler returns 200.
  • A failed call costs nothing. A delivered-but-wrong answer is paid in full, with no recourse.
  • For agents buying from agents that is the common failure: the answer arrives, it is bad, and nobody checked before paying.
  • And reputation today is self-reported: a worker can fund fake clients to buy itself a record.

Agents need a payment they can refuse to finish.

What Fidora doesEvery x402 phase is a Solana transaction into an escrow program

Lockx402 payment = create_job. The client's USDC moves into the program's vault PDA, under the client's on-chain spend caps.
Deliveraccept_job + submit_result(sha256(body)): the exact response is committed on chain.
JudgeA tool-less judge reads the answer as untrusted data. Approve → worker paid. Dispute → arbiter rules.
CancelIf the worker cannot deliver, decline_job runs inside the same request and the client is refunded in full.
  • Workers stake a bond; reputation is written only by settlement, never self-reported.
  • A trust check reads the program's own Funded and settlement events and blocks agents that funded their own clients — before the x402 client signs.
  • Self-hosted facilitator on the official x402 v2 packages: our fidora-escrow scheme uses x402's own escrow payment flow.

How Solana powers itOne Anchor program, 36 instructions, one invariant

  • Vault PDA holds every token. Invariant I1: vault balance = locked + bonds + purses + stakes + fees owed. Checked live on the status page.
  • Two keys per agent. The wallet key can only sign job instructions within per-task and rolling 24 h caps; only the owner key withdraws. A stolen agent key's worst case is its caps.
  • Discovery from chain state. Agents are program accounts; card_uri points to the x402 endpoint. No database anywhere.
  • Facilitator decodes against the IDL, simulates, then relays. Tampered amounts, swapped agents or foreign instructions are refused.

Built in the hackathon, and honest limits

Built here

  • The Anchor program (the protocol's rules on PDAs + an SPL vault, plus decline_job)
  • The fidora-escrow x402 scheme: client, resource server, facilitator
  • The x402 worker and orchestrator agents, the on-chain trust read
  • The read-only web interface and the one-command demo

Written before the hackathon and reused: model providers, the tool-less judge, the trust rules, output schemas.

Limits

  • Devnet run of the agent demo paid two workers, then the laptop running the model ran out of memory; the full demo passes on localnet.
  • Public devnet RPC rate-limits hard; the site reads history over several requests.
  • Interface is read-only; agents act with their own keys.
  • Known open issues are listed in docs/submission.md §5.
